## 2. `[GLIDE-DIAG]` — покадровый лог движения (TODO удалить)

**Где:** `FoveatedRender::UpdateEyeTrackingFoveation` в `FoveatedRender.cpp`,
внутри `if (subrectMovedThisFrame)`, между проверкой порога прибытия
(`remainingPx < 16.0f`) и re-arm deadzone. Добавлен коммитом `7d65ea43`.

**Зачем:** различить «один непрерывный глайд» и «два раздельных gate-трипа»
(двойную перерисовку) — 5-секундные diag-записи этого не показывают.

### Формат

На каждый движущийся кадр две строки (левый/правый глаз):

```
[GLIDE-DIAG] frame=12345 eye=L step=184.3 remain=520.7 drift=560.2 gate=-S- latch=0
[GLIDE-DIAG] frame=12345 eye=R step=445.9 remain=0.0   drift=445.9 gate=D-- latch=0
```

| Поле | Смысл |
|---|---|
| `step` | Шаг региона в этом кадре (px) — фактическое смещение `lastGazeOffset` |
| `remain` | Остаток до цели после шага (цель = сырой gaze, сам может дрейфовать) |
| `drift` | Дрейф gaze от позиции региона (то, что сравнивается с deadzone) |
| `gate` | Источник движения: `D` = dwell-трип, `S` = saccade-байпас, `-` = латч ещё активен |
| `latch` | Состояние `gazeGlideActive` после кадра (1 = глайд продолжается) |

Бюджет: **3000 строк за сессию** (static `glideLogBudget`), после исчерпания лог молчит.

### Как анализировать

- **Здоровый паттерн (текущий):** одиночные записи `gate=-S-`, `remain=0.0` —
  один saccade-трип = один полный прыжок в точку gaze, латч мгновенно снят.
- **Двойная перерисовка:** пары `S→D` — saccade-прыжок, затем через ~15 кадров
  dwell-прыжок к догнавшей цели. Классическая причина — цель на EMA-точке
  (устранено коммитом `04c5254f`, цель теперь сырой gaze).
- **Бегущий глайд:** серия кадров с `gate=--` (латч), `step` плавно убывает,
  `latch=1` до прибытия. Нормально для суб-1.0 glide.
- Если `remain` не убывает от кадра к кадру — цель уезжает от региона быстрее,
  чем регион догоняет (EMA-хвост сильнее ожидаемого).

## 3. История использования (что уже нашли этой диагностикой)

1. **Глайд на максимуме = серия телепортов.** При `glide=1.0` каждый трип давал
   `step == drift`, `remain=0` — латч не включался, «глайд» отсутствовал.
2. **Пары `S→D` = двойная перерисовка.** EMA-хвост цели (~10 кадров сходимости
   после саккады) накапливал заново deadzone → второй dwell-прыжок. Именно это
   пользователь видел как «картинка перерисовывается дважды».
3. **Фикс:** цель субректа переключена с EMA-точки на сырой gaze (`04c5254f`).
   Последующая сессия подтвердила: остались только одиночные `S`.
